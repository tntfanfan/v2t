# 分角色台词文档与学习脑图

交付可追溯的原文台词，并配套一张本集英语学习总结脑图；脑图不替代完整台词。角色身份、发声形式和文字准确性分开记录。自动识别结果是候选稿，不能直接充当已核对稿。

## 开始一集

1. 读取项目约定和 `pipeline.local.json`（存在时），按其中的路径读取角色总表、逐集索引与脑图模板。默认每集交付台词文档和脑图；用户明确只要其中一种时遵从。只处理指定集数；“下一集”按索引和现有素材确定，不擅自扩成整季。仅更新 skill 不自动补做历史集。原视频、音频、模板和已有交付稿保持不变，新版本放新目录。
2. 确认季集号、语言、文件、时长和时间轴。重名文件先比较 SHA256，相同文件只处理一次但不删除副本。独立音频不因名字相同就视为同步；抽查开头、中间、结尾并记录偏移。不匹配时优先使用视频内音轨。
3. 打开代表帧确认片名、字幕位置和角色外观。优先检查内嵌字幕流；烧录字幕用 OCR；缺字幕或字幕不全时使用 ASR 并回看音画。只使用能访问的素材，不把登录墙、DRM 或不可下载链接当成已读取。

读 [数据结构](references/data-schema.md) 后建立本集结构化稿。运行媒体工具前读 [本地工具与校验](references/local-workflow.md)。脚本均接收参数，不绑定某一集或某个盘符。

## 素材与输出目录

- 从项目根目录解析配置，不从个人 skill 安装目录解析。`pipeline.local.json` 的 `input_root`、`output_root`、`registry`、`episode_index`、`mindmap.template` 和依赖路径均相对于项目根目录；显式绝对路径按原值使用。
- 默认在 `input/` 查找原始素材，在 `output/<集号>/` 保存结果。当前项目的季目录位于 `input/第一季52集/`、`input/第二季52集/`、`input/第三季52集/`，保留季内视频、音频和分组结构。别的项目以其配置和用户要求为准，不强制套用这些季名。
- 角色参考和本集 sources 保存从项目根目录可解析的路径，如 `input/第一季52集/分集视频/1-2/S01E01.mp4`；不能漏掉 `input/`，也不能按 JSON 文件所在目录拼接。
- 将候选字幕、截图和 QA 文件放在本集输出目录的工作子目录，不写入 `input/`。既有交付不覆盖；重做使用新的版本或运行子目录。
- 执行前确认源文件和角色参考可访问。源目录迁移后检查配置、角色表、逐集索引与本集源记录；不要因引用失效擅自搬动素材或改写用户目录。

## 角色总表

- 每部剧一份 `series/<series_id>/characters.json`，它是身份信息的唯一数据源；CSV 是供查看的导出视图，不单独修改。逐集稿引用稳定的角色 ID。
- 名字、称呼和译名归入同一角色，例如爸爸与 Dad；别名匹配只是线索，不是声音识别器。
- 声音参考保存原片路径、哈希、时间段、语言或配音版本和确认依据。不仅凭音高、年龄印象、台词称呼或镜头中站着谁判断说话人。
- 为插图维护独立的已核对外观描述和原片参考帧，记录画面中具体是哪位角色；结构见数据结构参考。身份已确认不等于外观参考已核对，生成图不能反过来作为认人证据。更新总表前保留版本快照，历史交付继续引用当时版本。
- 总表中只将有证据的新角色标为 `confirmed`；暂定角色保留 `provisional`。修改已确认身份时记录原因及受影响集数，不批量改写旧稿。
- 将“说话人”和“发声形式”分开。角色在画外说话仍是角色；旁白、片名报幕、唱歌是发声形式，不必虚构为独立人物。报幕声音未确认时角色列表留空并注明“说话人待核”。
- 合声列出能确认的多位角色；无法逐一确认的片头合声使用群体标签，不强行分配给某一位。换配音版本时重新确认声音参考。

## 逐句整理

- 保留原句、重复、口语和被打断的表达；只修正有依据的识别错误与标点，不把不标准语法改成书面语。台词全文在用户未要求时不自动翻译；配套脑图按模板提供精选内容的中英双语解释。
- 每条保存起止时间、角色 ID、发声形式、原文、文字与说话人的核对状态、证据引用。一个字幕含两位说话人时拆分；真正同时说话保留重叠并说明，勿为通过检查伪造顺序。
- 结合原字幕、ASR、相邻镜头、口型及可用音频核对。不要声称听过无法实际播放或处理的音频。声音参考与画面证据不足时明确标疑点。
- 对每个候选字幕编号作出保留、合并、拆分或排除决定。片尾名单、台标及 OCR 噪声须给排除原因。抽查无字幕空档和转场，尤其是短感叹、画外对白及哼唱。
- OCR 采样区间不是精确语音边界。默认可用约 0.5 秒采样做候选稿，短台词附近加密；如用户要精确字幕，需另做语音对齐。文档说明实际时间精度，不承诺毫秒级准确。
- 不确定文字用局部 `[听不清]`、`[歌词待核]`；未知说话人单独标注。保持文字疑点和身份疑点独立，不能因文字清楚就认定角色。

## 每集学习总结脑图

完成本集台词核对后，读 [脑图模板与生成](references/mindmap-workflow.md)。使用配置中的 `mindmap.template`；本项目默认是 `input/template/Bluey_分集英语学习总结_思维导图参考模板.jpg`。模板作为版式和画风参考，不是其他集的剧情或语言证据。

沿用竖版儿童学习海报、中心主题与彩色分支、五个双语板块和学习提示。先整理文案与来源，运行 `scripts/mindmap.py validate` 和 `build-prompt`，再读取可用的 imagegen skill，使用内置图像生成工具制作配套脑图。原句逐字匹配已核对稿；脚本将原句、说话人和外观参考带入提示词，身份或外观未确认时只配中性道具。剧情概括和练习例句分开标示，不把练习混入原片对白，也不照搬模板内容。

脑图默认作为独立图片与文档一起保存到本集输出目录，不覆盖模板，也不擅自插入或改写已有 Word。生成后逐项检查文字、剧情、角色和布局；缺少模板或图像能力时仍可完成文档，但明确报告脑图未完成，不能用纯文字大纲代替成品图片并称全部完成。

## 生成与验收

1. 使用 `scripts/transcript.py validate` 检查角色引用、时间轴、来源覆盖与疑点。机器校验通过不代表内容核对完成。
2. 使用 `scripts/transcript.py export` 从同一 JSON 生成 Word；按项目约定附 TXT 和 SRT，避免各格式手工修改造成漂移。英文原文配中文角色说明是本项目默认，不是所有项目的强制语言。
3. DOCX 创作时使用可用的 documents skill，读取其要求，使用 bundled runtime 并遵守文档操作记录与逐页渲染校验。默认清晰标题、简短角色说明、时间码、加粗角色标签、自然场景标题；不要给每集套用第一集的情节和时间分界。
4. 渲染后查看所有页面，检查缺字、拥挤、分页和最后一句；工具无法渲染时如实标记为未完成视觉检查。不要仅凭 DOCX 可打开宣布验收通过。
5. 生成并验收本集学习脑图。分别记录文案、图片文字和整体视觉检查；台词结构校验及 Word 渲染通过不代表脑图通过。
6. 将文档与脑图的内容核对、视觉检查、疑点和交付路径分别记入本集 QA 文件和逐集索引。记录脑图所用台词与模板的路径、SHA256、生成方式、提示词路径和实际图片尺寸；详细字段见脑图参考。两类交付都通过相应检查后才能称本集交付完成。已有历史集不因新规则被改写为已生成脑图。
7. 最后给文档与脑图路径、图片预览、角色区分情况和剩余疑点；简要说明图像生成方式并链接所用提示词。不要附 OCR 截图、QA PDF 或模型缓存，除非用户需要。原稿不要被测试输出覆盖。

这是需要音画核对的代理工作流，不是保证全自动认人或零错字的一键转写服务。仅“使用此 skill”不授权上传原片到第三方、付费调用、批量下载模型或后台持续处理。
